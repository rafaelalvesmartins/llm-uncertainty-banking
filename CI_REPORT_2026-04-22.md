### Deferred (real findings, require schema change or behavior-breaking test updates)

These are documented here so they aren't lost; each would require a dedicated branch.

1. **`drift` CLI feeds aggregate metrics to PSI.** `src/lub/cli/inspect.py::drift` does `np.array(list(ref.metrics.values()))` — but `BenchmarkResult.metrics` is a `dict[str, float]` of scalar metrics (ECE, AUROC, Brier, ...), not per-example confidences. PSI over two ~15-element metric vectors is mathematically meaningless. Two existing tests (`test_cli.py::test_drift_between_two_results`, `test_e2e_cli_chain.py::test_full_cli_chain_benchmark_drift_report_repro`) only assert that the command exits 0 and produces `{"psi", "drift_level"}` keys, so they'd pass even with garbage numbers. Proper fix requires either adding `per_example_confidences: list[float]` to the `BenchmarkResult` schema or redefining the CLI contract to read a separate confidences JSONL. Both are breaking; leaving to a deliberate release.
2. **`MondrianConformalEstimator` unknown-group fallback is the loosest threshold.** `mondrian_conformal.py:116` does `threshold = max(self.thresholds.values())` for an unseen group, which is the *laxest* coverage bound — silently giving a new group the lowest bar. The existing test `test_score_unknown_group_returns_result` explicitly pins the current "falls back gracefully" behavior, so raising instead would be a breaking change. Leaving for a follow-up where the test and the contract are revised together.
3. **`MetricThreshold.classify` ordering not validated.** `reports/findings.py:72-84` does not enforce the invariant that `observation` is between `finding` and PASS relative to `higher_is_better`. A misconfigured instance silently collapses the OBSERVATION band. The dataclass is frozen; a `__post_init__` guard would be additive but might reject existing configs. Defer until a next cycle documents the invariant in the dataclass docstring first.
4. **`BenchmarkResult.n_errors` not persisted.** `BenchmarkRunner.run` tracks `n_errors` through the loop but never writes it into the `BenchmarkResult` payload — audit trails lose the count. Adding the field is a schema change; pydantic `extra="forbid"` means every old persisted file would stay readable but every serializer needs the new field.
5. **`rails.py` PII regex lacks Luhn validation** on the `credit_card` category — matches any 13–16-digit run with optional dashes/spaces, false-positives on phone numbers. Either add Luhn or rename the category to `long_digit_run`.
6. **Default magic numbers duplicated across estimators.** `temperature=0.7`, `max_tokens=256`, `refusal_threshold=0.5` are repeated in ~15 places. Extracting `DEFAULT_TEMPERATURE`/`DEFAULT_MAX_TOKENS`/`DEFAULT_REFUSAL_THRESHOLD` `Final` constants in `wrappers/base.py` + `types.py` would centralize the convention but touches every estimator signature; treat as cosmetic refactor, not a bug.
7. **`n_samples` inline validation.** Several estimators (`ccp`, `conformal_sampling`, `p_true`, `self_consistency`, `mahalanobis`, `eigenscore`) either have inline `if n_samples < N: raise` or skip the check entirely instead of using the shared `_validate_n_samples`. Normalizing is safe but touches many files; defer.
